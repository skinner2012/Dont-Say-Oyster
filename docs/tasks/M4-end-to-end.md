# M4 — Get one game running end to end

## Goal & exit criterion

See `SPEC.md`, Milestones, M4. Do not copy the bullets here; they go stale.

**Exit criterion:** Done when each of V0, V1, and V2 finishes one game at node F with a complete JSONL record.

- **Real:** the variant argument with the Challenger and corpus-lookup toggles, every model call and every output the program caught kept as the game runs, the per-game JSONL record that stands without the trace, one live game in each of V0, V1, and V2 recorded here, and the num_ctx check over those three games.
- **Absent:** no model, temperature, or thinking decision (M5); no memory toggle, node H, V3, or the record's memory fields (M6); no batch script, manifest fields beyond the card order, metrics, or charts (M7); no prompt tuning, which is the author's; no request timeout (Q2).

## How to use these tickets

T1 → T2 → T3 → T4 → T5, strictly in order: T1 adds the variant argument, so V2 is chosen by name and V0 and V1 become runnable, T2 keeps in State what the record needs and State did not keep, T3 writes the record, T4 is the three live games that close the milestone, and T5 reads their num_ctx evidence. T1–T3 are accepted by tests with scripted model outputs and the in-memory span exporter, so none needs Ollama or Langfuse; T4 and T5 are accepted by the record they leave in this file, so their Acceptance holds once the record commit has landed, and Status becomes done after the audit (`CLAUDE.md`, Milestones and tickets). One ticket, one commit; T4's three runs land as three record commits, V0, V1, then V2, so a fix found by one run lands before the next; Status updates, audit fixes, and the T5 decision are their own small commits. Two facts behind these tickets are not in the repo text: before T2, State's rows kept latency, tokens, and attempt only for the last description, answer, guess, and verdict and for each lookup, and B and E overwrite a sent-back output when the retry arrives, so the record's call list and caught outputs are kept as the game runs (T2), not reconstructed at the end; and the Langfuse spans carry role, attempt, kind, and round as attributes but not the ordinal, and the node only as the parent span's name, so the record, not the trace, is the source of the call list (`SPEC.md` Recovery, forks, and replay, Trace loss).
